# Step 6 — Nemotron-briefed hand-off to Claude Code / Codex

**Goal:** a channel line like "draft a fix for the checkout crash" becomes a
Nemotron-written brief. After the user says **go**, Claude Code (or Codex) runs
in a throwaway copy of the repo, and Nemotron reviews what came back against its
own brief. The result is a branch plus a receipt in the note. Nothing is pushed or
merged.

**Why this shape:** three of the four judging criteria name Nemotron. Nemotron
classifies the line, gathers evidence, writes the brief and judges the result.
The coding agent only does the edits, is optional, is disclosed, and brings its
own subscription. It is never the source of a decision.

## Flow

```
channel line ──► project (Super decides: kind=task) ──► tools ──► Super writes the brief
     └─► proposal reply in the note: goal · steps · done-when · "say go"
"go" (typed or Siri) ──► router code gate ──► approve (digest-bound, 24 h) ──► "On it"
listener tick ──► dispatch: git worktree + hand subprocess (no shell, no network tools)
listener tick ──► collect: commit on notron/<id>, diff, scope check, remove worktree
listener tick ──► report request ──► Super reviews diff vs brief ──► receipt in the note
```

## Decisions (defaults chosen; no user input needed)

1. **Grant:** `notron channel add X --allow read,run --hand claude|codex`. The
   `run` grant needs a repo and a hand, and it lives in the registry, never in the note.
2. **Approval every time (v1):** there is no unattended run. The approval binds to the
   SHA-256 of the exact brief shown, covers only the latest proposal in that
   channel, and expires after 24 h. Approval words are matched in code (`go`,
   `yes`, `do it`, `run it`…). `stop` cancels. The task board (step 7) adds a
   button over the same `approve(task_id, digest)`.
3. **Containment:**
   - Runs in a `git worktree` of HEAD under the data directory, so the user's
     checkout and uncommitted work are never touched.
   - Output is a local branch `notron/<id>`; nothing is pushed.
   - Stripped environment (no tokens, no Nebius key).
   - Claude Code runs with `-p`, `Read/Glob/Grep/Edit/Write` only, `Bash`/web/MCP
     denied, `--strict-mcp-config`, a max turn count and a 15-minute timeout.
   - Codex runs with `exec --sandbox workspace-write` (OS sandbox, network off).
   - Plain code checks that every changed path is inside the project folder. A
     change outside it is reported, not hidden.
4. **Invariant 5:** the brief reaches the external agent through
   `prepare_outbound('delegate', …)`, like every other model input.
5. **Delivery:** a report is an ordinary graph request (`trigger="task"`,
   request id `task-report:<id>`, so it can never be posted twice). It runs under
   the watcher's reply capability for the channel note. It appends through the
   Guard/Executor, and the task is marked reported only when
   `receipt_complete` is true.
6. **Storage:** tasks are encrypted (`securestore.write_json`,
   `data_dir()/tasks.json`). Raw agent output lives only in the private run
   directory until collected.

## Tasks

1. `channels.py`: add the `run` grant and the `hand` field, the CLI flags `--hand`, and
   validation. Tests.
2. `handoff.py`: store (propose/approve/cancel/get/list, with digest and expiry),
   hand argv builders, dispatch/poll/collect with an injectable `_spawn`/`_git`.
   Tests use fakes, with no real claude/codex/git.
3. `nodes.py`:
   - `BRIEF_SYSTEM` and a second Super call for `kind=task` with `run`.
   - Router gates for `approve`, `cancel` and `report`.
   - Deterministic replies for these intents; the writer does not call a model.
   - `REVIEW_SYSTEM` for the report. Tests.
4. `watch.py`: `check_tasks()` in the tick (collect → dispatch one → report
   one). Tests.
5. `cli.py`: `notron tasks list|show|approve|cancel [--json]`. Update `CLAUDE.md`. Tests.
6. Live proof on a scratch repo channel: propose → go → run → report.
   Record the timings.
