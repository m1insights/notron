# P02 Task 6 — Worker lifecycle, queue health and migration

Base: `365fe7b`; implementation commit: `435d061`, followed by the maintenance-outcome correction; branch `production/p01-task1`; existing worktree `.worktrees/p01-task1`.

## Behavior and interfaces

- `notron listen --status` returns JSON version **1**: `state`, `heartbeat_at`, `last_success_at`, `pending_count`, `reason_code`, and compatibility `running`. UTC timestamps describe heartbeat and completed work separately. Unknown/unreadable queue metadata returns `state=error`, `reason_code=storage_unavailable`, and `pending_count=null`, never a misleading zero. Launchd registration alone is not readiness. The kernel worker lock and a heartbeat no older than 30 seconds establish liveness.
- States are `starting`, `ready`, `paused`, `offline`, `permission_needed`, `error`, `stopped`. A separate thread updates heartbeat every **5 seconds** without decrypting payloads, calling providers, or querying Apple apps. Credential/storage failures pause processing; dependency checks must succeed before work resumes. `--pause`/`--resume` persist intent independently of Keychain. Pause stops new-job admission; an already admitted job finishes its guarded work. `--off` also requests foreground listener shutdown, checked between jobs; launchd bootout remains the managed-process stop mechanism. Foreground restart and explicit install clear stop intent, while preserving pause intent.
- Listener, CLI ask/plan/file/index/care/reflect/morning, direct morning calls, and graph/filing request admission share **request-execution.lock**. Reentrancy belongs to one PID/thread; another local process cannot claim work. CLI producers persist encrypted jobs before executing. A busy producer returns a JSON job reference instead of starting a second executor. One-shot owners drain accepted queued jobs before exit; an admission mutex closes the final empty-check/release race. Setup refuses concurrent execution because it precedes a ready policy.
- Queued CLI and morning envelopes retain their original capture timestamp and IANA timezone. On restart/resume, readiness checks and existing request recovery precede fresh jobs. Sleep/clock gaps clear typing-settle state. Mention priming is retried after failure; a changed note's read debt is saved before its new timestamp, so a crash cannot lose an unobserved tag.
- Running generic maintenance jobs become review-required after interruption. Ask/file/plan jobs recover only through existing durable request/checkpoint rules. A completed graph request clears its stale queue entry after receipt repair. Care/reflection write refusals keep maintenance jobs review-required; a completed morning plan alone cannot hide failed reflection or care writes. Corrupt individual queued payloads are quarantined and do not block later jobs. Known applied actions are not recreated; uncertain Apple outcomes continue to require review.
- Provider calls have absolute **30-second interactive** deadlines and **60-second filing/index** deadlines. Filing entry points and morning indexing set batch context. Nebius inference, embeddings, and Tavily search use bounded retry handling with jitter; model-list probes use one bounded attempt; SDK automatic retries remain disabled. HTTP transient failures and transport outages back off; policy/credential/fixed HTTP rejection failures do not secretly retry. Each retry shares its logical call's deadline, including Nemotron's empty-reasoning retry. Embedding batches share one deadline for the `embed` call.
- Hard interruption of blocking synchronous DNS/body reads uses the main worker thread's timer; provider calls from other threads fail closed before transport. There are no abandoned background provider calls. Provider state is partitioned by service, so a Tavily outage does not put Nebius into cooldown. Models probes do not reset an unresolved inference cooldown history.

## On-disk contracts and retention

- Existing `operations.sqlite3` remains **schema 3**. Its request identity, operation state machine, revision checks, encrypted checkpoints, and undo semantics are preserved. Newly recognized legacy occurrences commit directly as `needs_review` with `legacy_unknown`; this is a fixed request failure code, not replay authorization.
- New `worker.sqlite3` is **schema 1**, with `health`, `jobs`, and `cooldowns`. SQLite uses WAL, FULL synchronization, short transactions, private files/directories, and symlink rejection. Health/intent/queue metadata contains IDs, hashes, states, fixed reason codes, and times; it contains no user request text. Unknown schemas fail closed.
- Queued argument/envelope content is stored under `worker-payloads/job-*.enc` using the existing Keychain-protected encryption key. At most **200** queued/running/review jobs are admitted. Completed payloads are deleted while ID/argument-hash tombstones remain. Startup/retention removes unreferenced ciphertext left by an interrupted publication or deletion. Permission changes purge duplicated queued request payloads while retaining review tombstones. Content-free terminal identity history is deliberately retained rather than reset to force retries.
- Watcher retry keys are hashed in `cooldowns`, bounded to **1,000** recent entries; two unsuccessful attempts trigger the existing 30-minute rest across restarts. Provider cooldowns live in `provider.json`, containing only per-service failure counts and retry timestamps; corrupt/nonfinite/symlink state fails closed. No error/provider response bodies go into status metadata.

## Legacy migration

1. Stop existing executors and preserve the entire storage generation before upgrade. Existing P01 `storage migrate`/`storage accept` remain explicit offline actions. Migration performs no model or native-app calls. Validated, unused control files created by status/pause no longer block fresh key provisioning or migration. A queue with any prior jobs, encrypted payloads, unknown schema, arbitrary files, or a preexisting key still cannot be treated as empty storage.
2. Scanner JSON moves from unversioned/v1 to **version 2**, preserving seen timestamps/pending IDs and adding review IDs. An encrypted, verified `worker-backup/seen-v1.enc` is written before replacement. Unknown existing Ask/tag occurrences become review-required; ledger-backed pending identities remain intact. Corrupt scanner state is preserved and blocks initialization instead of resetting history.
3. P01 offline migration writes an encrypted **worker-history version 1** marker carrying scanner metadata and an uncertainty flag for old filing judgments/proposals. Those judgments are not executable plans. Existing encrypted filer caches are backed up to `worker-backup/filer-v1.enc` before the lifecycle migration publishes its marker.
4. If old filing outcomes cannot be established, automatic filing stays blocked for review. This task deliberately supplies no automatic “clear and replay” option. P06's review/recovery UI can present the evidence; operator recovery must reconcile effects before changing the gate. Normal user notes, original Brain Dump lines, and the existing action/undo ledger are preserved.
5. Raw in-place filer backup content is retired when its policy changes or a source deletion invalidates the inventory; the content-free review gate survives. P01 migration backups retain their existing explicit acceptance/deletion lifecycle. Scanner backup contains only observation metadata.

## Rollback

- Stop every worker first. Back up the **whole** private storage directory together with its Keychain key; SQLite databases, sidecars/checkpoints, encrypted payloads, worker intent, and migration markers form one recovery set. Never replace a missing key, delete the ledger, reset pending jobs, or restore only one database to make a retry run.
- Prefer rolling forward with preserved identities. An older build does not understand worker queue schema/intent or scanner v2 semantics; do not run an old automatic listener against pending migrated work. Keep it stopped while an operator reconciles queue and native effects.
- A pre-migration backup is not permission to replay effects that occurred afterward. Restoring old seen/filer state after later Apple writes requires explicit reconciliation. No live downgrade or native recovery was exercised in this task.
