## Outcome and contract

- ID-bound `Write`/`capture_write`/`Executor.apply_write`, with SHA-256 revision
  captured before inference. Organizer, planner, watcher/reply/Memory, care,
  reflection and filing use guarded targets. No model executes in the write path.
- Reentrant local thread/process transaction lock; immutable encrypted operation
  payload, required encrypted backup, final target/source/revision/policy checks,
  post-write read and durable observed revision. Unknown write outcomes pause for
  review; same operation cannot blindly reapply. Notes mutation adapters have no
  hidden timeout retry. Explicit approved creation never appends to a title twin.
- Stale replace/restore refuses. Stale append/insert/mark requires unambiguous
  captured anchors; captured positions disambiguate only unchanged bodies. Journal
  append layout never rebases. Filing holds source IDs/revisions through copy/tick,
  checks changed/deleted/ambiguous source lines before copying, excludes duplicate
  master titles, and reclassifies legacy title-only cached destinations.
- Conservative supported HTML validation refuses rich replacements; organizer
  returns separate text without writing the rich original. Failed writes cannot
  leave organizer/undo success wording. Audit uses the same guarded path and
  preserves verified primary success even when logging fails.
- SQLite schema 2 atomically migrates v1 with nullable observed_revision, retaining
  identity, encrypted payloads, history markers and tombstones. `finish` preserves
  a request already marked needs_review by approved creation's add_home policy
  update; no purge/revocation relaxation or replay reset.
- Stack: Python 3.11+ (verified with existing Python 3.14.2 root venv), stdlib
  SQLite/threading/fcntl, existing encrypted store, AppleScript adapter. No new
  dependencies, Swift changes, provider or model changes. Nebius Nemotron routing/
  writing and Qwen embeddings remain configured; no AI/provider call ran.

See `docs/production/design.md` P02 Task 2 contract for precise APIs and limits.

## Limits, follow-up ownership and rollback

- Remote Notes/editor/iCloud writers do not honor the local lock. Apple has no CAS;
  edits inside the final read/write gap can still be overwritten without a visible
  post-write mismatch. A synthetic test demonstrates that exact residual limit.
- Native metadata AppleScript behavior, real HTML normalization, permission prompts,
  multi-device races and rich-content fidelity are not verified by these tests.
  Conservative rejection may refuse ordinary but unfamiliar Apple formatting.
- Task 3 owns asynchronous audit/receipt reconciliation, cross-effect filing repair,
  and action adapters. APPLIED is verified Notes body evidence, not a final receipt.
  Approved creation may finish needs_review after add_home purges the active request;
  same request replay is blocked, including purged-payload refusal.
- Task 4 owns durable undo peek/verify/consume and snapshot provenance. Undo still
  pops before restore; backup writes can overwrite an older slot before a later
  final check refuses. This task prevents stale restore proposals from overwriting
  later edits but does not claim the complete undo lifecycle is implemented.
- Task 6 owns worker-wide lifecycle/leases, maintenance-job admission and legacy
  migration. P06 signed startup pause remains; this does not authorize real use.
- Rollback preserves a matched ledger/payload backup. Schema-1 code rejects schema 2;
  use schema-2-compatible code or a deliberate matched backup restore, never delete
  identity/tombstone files or reset the ledger to force retry. No automatic downgrade.
- No merge, push, deployment, release, dependency install or real data migration.
