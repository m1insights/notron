## What was actually wrong

The Sunday assessment listed four Stage One blockers. All four were real, and
the root cause of the largest one was not what the list implied.

| Blocker | Status after this session |
|---|---|
| Repo private (`404` unauthenticated) | **Fixed** — public, MIT detected in the About/README sidebar |
| 59 commits unpushed | **Fixed** — `main` == `origin/main` |
| 57 failing tests | **Fixed** — 1344 passed, 0 failed |
| venv 3.14.2 vs declared 3.11 floor | **Fixed** — suite verified green on 3.11.14 |

**The 57 failures were an isolation bug, not a transport bug.** All 57 were in
`tests/test_managed_transport.py` and every one died in the same place:
`transport._identity` → `securestore.private_directory` → `os.chmod` on
`~/Library/Application Support/com.m1labs.notron`. `transport` imports
`paths.DATA_DIR` *inside the function*, so it resolves at call time — which is
precisely the case no disposable-state fixture covered. Every other module binds
`DATA_DIR` at import into its own constant and has its own fixture. Here there
was none, because it looked covered. **On this machine those 57 tests were
performing silent live writes to real application state**; they only turned into
loud `PermissionError`s because this session's runner could not chmod outside
its own workspace. That is the same class of incident as the 2026-09-03 leak
that put fourteen junk `📊 Log` notes in the developer's own library, and it
contradicts the stated invariant that a test must never touch the real one.

`notron/paths.py` was four lines with no override. It now reads
`NOTRON_DATA_DIR` via `data_dir()`, and two guards hold the line — because one
is not enough: `health.py` binds `private_directory` at import into its own
namespace, so patching the name in `securestore` alone would have missed that
route. `os.chmod` is guarded too, since every route into real state ends there
whichever module called it.

**The 3.11 violation was real and total.** `cli.py:140` used
`f"  {'\u2713' if result.ok else '\u2717'} …"`. A backslash escape inside an
f-string replacement field is PEP 701, valid on 3.12+, a `SyntaxError` on 3.11.
Confirmed against the real 3.11 interpreter:
`SyntaxError: f-string expression part cannot include a backslash`. On the
declared floor `python -m notron` could not run at all.

**CI could not have caught it.** The Python job pinned 3.12 while
`pyproject.toml` declared a 3.11 floor. The matrix is now `['3.11', '3.12']`.

## Two things this work exposed that are not fixed

**1. `mac/Package.swift` declares a macOS 14 floor that nothing verifies.**
The `native-account` job failed on `macos-14` with `error: fatalError` and no
primary diagnostic, *after* the log reported every source file as compiled. The
real errors were above it: `reference to captured var 'self' in
concurrently-executing code` in `Library.swift`, `NotronApp.swift` and
`Onboarding.swift` — the `guard let self` pattern inside `MainActor.run` nested
in `Task.detached`. The same sources build clean in a from-scratch
`swift build` against the macOS 26 SDK (~6s), and on `macos-26` the identical
diagnostics appear as **warnings** carrying `this is an error in the Swift 6
language mode [#SendableClosureCaptures]`. The job now runs on `macos-26` and is
green. Two consequences:

- `platforms: [.macOS(.v14)]` is unverified and should be raised or proven on
  purpose. This is the same shape of bug as the Python floor: a declared floor
  CI did not test.
- That pattern is a **latent Swift 6 language-mode break**, currently only a
  warning (88 occurrences). Moving `swift-tools-version` past 5.10 turns all 88
  into errors. Worth a deliberate decision before any Swift 6 migration, and it
  is unrelated to this week's Python work — `mac/` was untouched.

**2. The public README still describes a Notes-centric product.** It is honest
about scope (`**Planned, not shipped:**`, and the demo/deadline targets are
stated), which is better than the assessment implied. But the narrative has not
been updated for the reframe agreed this session — Notron as a control plane
over projects and external agents, with Notes demoted to one surface among
three. That is submission-narrative work, not Priority Zero, and it belongs with
the README/submission pass rather than here.
